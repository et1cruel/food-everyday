# Master Prompt — FOOD EVERYDAY

คุณคือทีมผลิตภัณฑ์ ออกแบบ และพัฒนาเว็บ FOOD EVERYDAY จงทำให้คลังอาหารไทยและอาหารโลกกลายเป็นเครื่องมือทำอาหารประจำวันสำหรับคนที่มีเวลาน้อยและเพิ่งเริ่มกินผัก เปลี่ยนจากการเลือกเมนูไปสู่การลงมือทำจริงภายในเว็บเดียว วัดผลจากขั้นตอนที่ผู้ใช้ทำสำเร็จและความถูกต้องของข้อมูล

## งานที่ต้องส่งมอบ

1. คงสูตรเดิมทั้งหมด ชื่อ ลิงก์ ไอดี วัตถุดิบ เรื่องราว วิธีทำ ภาพถ่ายจริง และเครดิตเดิม รักษารายการโปรดที่บันทึกในเบราว์เซอร์ โหมดสุขภาพยังเป็นค่าเริ่มต้น
2. ให้ผู้ใช้เลือกของที่มีในครัว แล้วเรียงเมนูตามจำนวนวัตถุดิบที่ตรง แสดงชื่อของที่ตรงบนการ์ด ใช้ชื่อและคำพ้องที่คัดจากข้อมูลวัตถุดิบ เช่น มะเขือเทศตรงกับมะเขือเทศเชอร์รี และไม่จับข้าวโพดจากชิปข้าวกล้อง รองรับการกรองร่วมกับประเทศ วิธีปรุง เวลา และชุดสูตรใหม่
3. เพิ่มหน้าวางแผนมื้อแบบรายสัปดาห์ เลือกมื้อเช้า กลางวัน หรือเย็น เปลี่ยนสัปดาห์ และเพิ่มอาหารมากกว่าหนึ่งจานในมื้อเดียวได้ บันทึกจำนวนที่ของแต่ละจาน แสดงสถานะหลังเพิ่มและให้ลบทีละจาน
4. ทำรายการซื้อของจากแผนสัปดาห์ รวมเฉพาะรายการวัตถุดิบที่ชื่อและหน่วยตรงกัน ปรับตามจำนวนที่ ติ๊กของที่มีแล้ว คัดลอกรายการ และเก็บสถานะรายสัปดาห์ อย่าเดาการแปลงหน่วยชนิดต่างกันและอย่าทำปริมาณที่เขียนว่า “ตามชอบ” กลายเป็นตัวเลข
5. ในหน้าสูตรให้เลือก 1–8 ที่ ติ๊กวัตถุดิบ เปิดโหมดอ่านวิธีทำทีละขั้น ตั้งเวลาจับจากเวลาสิ้นสุดจริง และแชร์ลิงก์สูตร ปรับเฉพาะปริมาณที่อ่านได้ชัด เก็บข้อความเดิมสำหรับรายการซับซ้อน และระบุว่าขนาดหั่น อุณหภูมิ และเวลาปรุงยังอิงสูตรต้นฉบับ
6. สร้างหน้าสูตร HTML ที่อ่านได้จากลิงก์ตรงแม้ปิด JavaScript มีชื่อ คำอธิบาย ข้อมูลสำหรับแชร์ และเครดิตภาพ มีลิงก์กลับไปยังโหมดทำอาหาร เก็บเส้นทางเดิมที่ใช้ query string และทำ sitemap จากคลังจริง
7. เก็บแผน รายการซื้อของ วัตถุดิบในครัว และรายการโปรดในเบราว์เซอร์ แสดงสถานะสำรองเมื่อจัดเก็บไม่ได้ ให้ข้อมูลที่เสียหายหรือไม่มีแล้วถูกข้ามโดยยังเปิดเว็บได้

## ทิศทางการออกแบบ

ใช้เขียวสน #173c32 พื้นกระดาษ #f7f6ef ขาวอุ่น #fffef9 เขียวใบอ่อน #dceda9 และเขียวหม่น #4d6459 คง Noto Sans Thai สำหรับข้อความภาษาไทยและ DM Sans สำหรับเลขและข้อความสากล รักษาหัวข้อ “วันนี้กินอะไรดี?” ให้อยู่บรรทัดเดียวบนจอ 320 พิกเซลขึ้นไป

หน้าแรกวางภาพอาหารจริงและช่องทางเข้า “ค้นหาเมนู” คู่กัน แล้วแสดงเครื่องมือครัวติดกับแค็ตตาล็อก ใช้ชื่อวัตถุดิบเป็นปุ่มเลือกสั้น ๆ เสมือนของที่ผู้ใช้แตะหยิบจากตู้เย็น ใช้พื้นที่ว่างและเส้นแบ่งคล้ายสมุดสูตรอาหารกับแผนมื้อรายวัน ให้แผนอ่านตามวันและมื้อได้ทันทีบนมือถือ ใช้รูปจากคลังเดิมและเครดิตเดิม ไม่ใส่ภาพสต็อกที่ไม่เกี่ยวกับสูตร

- เดสก์ท็อป [ ภาพนำ + พาดหัว ] → [ ชื่อส่วน + โหมดสุขภาพ ] → [ ค้นหา / ตัวกรอง / ของในครัว ] → [ การ์ด ]
- มือถือ [ พาดหัว ][ ภาพนำ ] → [ ค้นหา ][ ตัวกรองที่ตัดขึ้นบรรทัดได้ ][ การ์ด ]
- แผนมื้อ [ สัปดาห์ก่อน / ช่วงวันที่ / สัปดาห์ถัดไป ] → [ วันและมื้อ ] → [ รายการซื้อของ ]

## เกณฑ์รับงาน

- เปิดสูตรเดิม รายการโปรดเดิม และตัวกรองหมวดเดิมได้ จากชุด 350 เมนูต้องยังเห็น 50 สูตรต่อหมวด
- เลือกของจากครัวแล้วได้ผลลัพธ์ที่มีของตรงจริง ปิดตัวกรองแล้วออกจากมุมมองนั้นได้ แผนและรายการติ๊กยังอยู่หลังรีโหลด
- ลองปรับปริมาณทั้งตัวเลข เศษส่วน ช่วง และรายการคลุมเครือ ทดสอบไม่รวมหน่วยคนละชนิดและไม่เอารายการจากสัปดาห์ข้างเคียงมาคิด
- ใช้ Tab, Enter, Escape และปุ่มย้อนกลับได้ หน้าจอ 320 พิกเซลไม่มีการเลื่อนแนวนอน แจ้งสถานะสำคัญโดยไม่แย่งโฟกัส
- ตรวจ npm test และ npm run build ทดสอบด้วยเบราว์เซอร์ผ่านหน้าแรก หน้าสูตรที่มีและไม่มี JavaScript และวงจรครัว → สูตร → แผน → ซื้อของ ตรวจปริมาณจริงจากผลลัพธ์
- Push ไปที่ et1cruel/food-everyday และ deploy ไป Cloudflare Pages โปรเจกต์เดิม ทดสอบจากโดเมนจริง พร้อมสรุปสิ่งที่ส่งมอบและขอบเขตที่ทดสอบ
